# План смены домена и запуска

## До смены домена

1. Зафиксировать текущие страницы старого проекта.
2. Составить карту старых и новых URL.
3. Подготовить новый сайт на техническом домене или staging-поддомене.
4. Проверить, что в текстах, настройках темы, формах и письмах нет жесткой привязки к старому домену.
5. Настроить резервные копии.
6. Проверить SSL на новом домене.

## При смене домена

1. Привязать новый домен к хостингу.
2. Выпустить SSL-сертификат.
3. Обновить WordPress Address и Site Address.
4. Заменить абсолютные ссылки старого домена на новый домен.
5. Настроить 301-редиректы со старых URL на новые релевантные страницы.
6. Обновить sitemap.xml и robots.txt.
7. Добавить новый домен в Яндекс Вебмастер и другие панели.

## После запуска

1. Проверить главную страницу, каталог, карточку товара, корзину и оформление заказа.
2. Проверить формы обратной связи и быстрый заказ.
3. Проверить оплату в тестовом режиме, затем в боевом.
4. Проверить уведомления менеджеру и клиенту.
5. Проверить цели Яндекс Метрики.
6. Проверить мобильную версию.
7. Запустить индексацию sitemap.xml.
8. Ежедневно мониторить ошибки 404 и статусы заказов первые 1–2 недели.

## Карта редиректов

Для каждого старого URL нужно указать новый URL:

| Старый URL | Новый URL | Тип |
| --- | --- | --- |
| `/` | `/` | 301 |
| `/catalog/` | `/catalog/` | 301 |
| `/contacts/` | `/contacts/` | 301 |

Если старой страницы больше нет, редиректить не на главную автоматически, а на ближайшую по смыслу категорию или информационную страницу.
